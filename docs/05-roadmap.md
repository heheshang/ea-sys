# 路线图与风险

## 1. 里程碑

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| M0 | 工程骨架：多模块（api / engine / agent / channel / common）、Flyway 基线、租户上下文、JWT 鉴权 | 空工作流请求链路跑通 |
| M1 | contact + audience 圈选 API | 规则圈选出人群，快照冻结 |
| M2 | DAG 引擎：节点模型、解析、状态机、干跑 | 画布保存 → 发布 → 干跑报告 |
| M3 | 触达执行：短信 / 邮件适配器、模板、幂等、频率控制、回执 | 一个「条件 → 短信」流程真实触达 |
| M4 | 智能体：分层 / 路由 Agent 接入，schema 校验 + 确定性降级 | 仅手机号走短信、双通道按 DAG 顺序 |
| M5 | 留存看板：漏斗 / 留存 / 渠道效果；流失预警 Agent；AB 与灰度 | 运营凭数据迭代 |

**MVP = M0–M3 + M4 的确定性降级路由**：无 LLM 也能上线运营（仅手机号 → 短信是纯规则），智能体作为增量智能层叠加。微信通道在 M3 之后按需接入，画布与 SPI 已留位。

## 2. 风险与对策

| 风险 | 对策 |
|---|---|
| 触达过度 = 流失加速 | 频率上限、静默期、退订优先于一切；这是留存系统，不是群发系统 |
| 智能体幻觉 | schema 约束 + 断言 + 置信度阈值 + 确定性降级 + 全量审计 |
| 短信成本失控 | 干跑预估 + 预算熔断 + 队列削峰 |
| 事件洪峰打爆通道 | 实时触发不豁免限流，Redis 令牌桶削峰 |
| 多租户数据越界 | 行策略 + 租户隔离测试用例纳入 CI |

## 3. M4 实施顺序

1. `agent-sdk`：AgentExecutor + schema 校验 + fallback + 审计基建
2. 分层 Agent（含确定性 fallback）→ 与人群引擎联调打标
3. 路由 Agent（单用户决策）→ 接入分流节点
4. 分层 / 路由的运营配置界面（维度选择、模型档位、置信度阈值）
5. 流失预警 Agent（M5，依赖留存数据就绪）

## 4. 后续决策点

| 事项 | 决定时机 |
|---|---|
| 条件表达式引擎（Aviator / QLExpress）| M2 |
| 分布式调度（Quartz 自管 vs XXL-Job）| M2 |
| 短信供应商（阿里云 / 腾讯云）| M3 |
| 消息队列（RocketMQ 5.x vs 起步 Redis Streams）| M0 基建 |
| 微信通道（企微 / 服务号 / 小程序）| M3 之后 |
