# 工作流引擎设计

## 1. 节点类型

| 节点 | 语义 |
|---|---|
| TRIGGER 触发 | 定时 / 事件 / 手动 / API / 立即，工作流入口 |
| CONDITION 条件 | 属性·标签·事件判断，多出口分支 |
| AGENT_SPLIT 智能体分流 | 智能体动态分层 / 路由 → 多出口 |
| DELAY 延迟 | 相对时长 / 固定时刻 |
| ACTION 动作 | 通道 + 模板，对到达该节点的人群子集发送 |
| UPDATE 更新 | 打标签 / 写属性（分层结果落库，供下次圈选复用）|
| END 结束 | 流程终止 |

## 2. 触发双模式

| 模式 | 子类型 | 说明 |
|---|---|---|
| 定时触达 | Cron 周期 / 指定时刻一次性 | 到点圈选人群快照入 DAG，支持租户时区 |
| 立即触达 | 事件 / 手动 / API / 发布即执行 | 事件实时入账即触发；手动对选中人群立即执行；API 由外部系统调用；发布即执行在工作流发布成功后立即对配置人群执行一次 |

**子类型明细**：

| 子类型 | 典型场景 |
|---|---|
| 事件触发 | 新客注册 → 立即发欢迎短信；下单支付 → 即时通知 |
| 手动触发 | 大促前圈定目标人群，点「立即执行」 |
| API 触发 | 外部 CRM / 商城系统调用接口，携带用户维度数据入流 |
| 立即触发（IMMEDIATE） | 流程发布后立刻对圈选人群跑一遍（如大促开场即发首波触达），每次发布执行一次 |

**调度实现**：

- 定时：分布式调度（Quartz / XXL-Job）+ Redis 锁防双跑
- 事件 / API：RocketMQ 实时消费，直接创建 execution
- 手动：直接创建 execution（快照已就绪）
- 立即：发布成功后同步圈选快照创建 execution（trigger_type=IMMEDIATE）

**人群语义差异**：

- 定时 / 手动 / 立即 → 触发时圈选快照（面向一群人的批量流）
- 事件 / API → 单用户入流（面向一个人的实时流，画像实时读取）

**治理不豁免**：立即触达同样过频率控制、静默期、退订检查 —— 实时不豁免限流，否则事件洪峰（如大促下单潮）会打爆短信通道。

## 3. 条件规则 DSL

结构化 JSON 规则，编译为可执行谓词；不用字符串 SpEL（防注入、可版本化、可干跑统计），表达式引擎在身边（如 Aviator / QLExpress）选型在 M2 定：

```json
{
  "op": "AND",
  "items": [
    {"field": "event.amount", "op": ">", "value": 100},
    {"field": "contact.layer", "op": "in", "value": ["L1", "L2"]},
    {"field": "contact.churn_risk", "op": "equals", "value": "HIGH"}
  ]
}
```

支持字段：`event.*`（触发事件数据）、`contact.*`（画像与分层标签）、`history.*`（近期触达统计）。

## 4. 执行语义

- 「人 × 事件」产生一个 `execution`，节点状态机：`pending → running → done / failed`
- 并行分支独立推进；失败指数退避重试，超限进死信队列
- 中断恢复 / 重跑基于 `execution_node_state`，不重复已完成的节点
- **干跑模式**：发布前用样本人群模拟执行，输出各节点预计触达人数与成本，运营确认后才真实下发

## 5. 治理

| 项 | 机制 |
|---|---|
| 幂等 | `delivery_record` 唯一键 `(tenant_id, contact_id, execution_id, node_key)` 防重 |
| 频率控制 | 租户级每日上限 + 用户级近期触达去重（Redis 计数 + 令牌桶削峰）|
| 静默期 / 退订 | `contact.status` + `suppression` 全覆盖，优先级高于一切 |
| 成本熔断 | 干跑预估 + 租户配额 + 超限告警 |
| 发布闸门 | 计划校验报告 `decision=BLOCKED` 阻止发布；强制发布需审批并留审计 |
| 版本化 | 工作流发布后改动升版本，进行中执行不受影响 |

## 6. 典型闭环示例

- **定时**：首购后 7 天未复购（Cron 每日扫描）→ 分层智能体 → 双通道按 DAG 顺序触达。
- **立即·事件**：`ORDER_PAID` 事件 → 单用户入流 → 条件节点「金额 > 100？」→ 高价值分支立即发短信 + 24h 延迟后发邮件。
- **立即·手动**：运营圈定「近 30 天活跃未付费」人群 → 手动触发 → 全链路立即执行。
